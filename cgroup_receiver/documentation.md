# cgroup

## Default Metrics

The following metrics are emitted by default. Each of them can be disabled by applying the following configuration:

```yaml
metrics:
  <metric_name>:
    enabled: false
```

### container.memory.events

Memory events of the container cgroup and its descendants, from `memory.events`.

`max` counts how often usage hit `memory.max` (each one starts reclaim), `oom` how often the OOM killer was invoked and `oom_kill` how many processes it killed.

| Unit | Metric Type | Value Type | Aggregation Temporality | Monotonic | Stability |
| ---- | ----------- | ---------- | ----------------------- | --------- | --------- |
| {event} | Sum | Int | Cumulative | true | Development |

| Name | Description | Values | Requirement Level | Semantic Convention |
| ---- | ----------- | ------ | ----------------- | ------------------- |
| type | Event counted in `memory.events`: `high`/`max` limit hits, `oom` (OOM killer invoked) and `oom_kill` (processes killed). | Str: ``high``, ``max``, ``oom``, ``oom_kill`` | Required | - |

### container.memory.file

Page cache charged to the container cgroup, from `memory.stat` `file`.

Includes the mapped binary and libraries, unmapped file cache and shmem/tmpfs. Clean file pages can be reclaimed. Together with `container.memory.rss` (anon) and `container.memory.kernel` it adds up to approximately `container.memory.usage`.

| Unit | Metric Type | Value Type | Aggregation Temporality | Monotonic | Stability |
| ---- | ----------- | ---------- | ----------------------- | --------- | --------- |
| By | Sum | Int | Cumulative | false | Development |

### container.memory.file.mapped

Page cache mapped into process address spaces, from `memory.stat` `file_mapped`.

The part of `container.memory.file` processes have mapped, such as executable binaries. The rest is unmapped cache, which is not part of any process RSS.

### container.memory.limit

Memory limits of the container cgroup, from `memory.high`, `memory.max` and `memory.swap.max`.

No data point is reported for a limit set to `max` (unlimited). When usage reaches `memory.max` the kernel reclaims inside the cgroup and, if that fails, OOM kills the container.

### container.memory.pressure.stall_time

Time tasks in the container were stalled waiting on memory (reclaim, refault I/O), from the container cgroup's `memory.pressure` `total=`.

Pressure stall information (PSI). `full` close to 0 means reclaim was invisible to the workload; a steadily rising `full` means the workload is losing wall-clock time to memory pressure.

| Unit | Metric Type | Value Type | Aggregation Temporality | Monotonic | Stability |
| ---- | ----------- | ---------- | ----------------------- | --------- | --------- |
| s | Sum | Double | Cumulative | true | Development |

#### Attributes

| Name | Description | Values | Requirement Level | Semantic Convention |
| ---- | ----------- | ------ | ----------------- | ------------------- |
| type | `some`: at least one task was stalled on memory. `full`: all non-idle tasks were stalled at the same time. | Str: ``some``, ``full`` | Required | - |

### container.memory.workingset.refaults

Reclaimed pages that were faulted back in while the kernel still remembered them, from `memory.stat` `workingset_refault_*`.

A rising file refault rate means reclaim is evicting pages that are still in use (thrashing).

### k8s.node.memory.limit

Memory limits of the node's root cgroup, from `memory.high`, `memory.max` and `memory.swap.max`.

The real root cgroup has no limit files, so this is only reported when the root is a namespaced cgroup (e.g. a kind node). No data point is reported for a limit set to `max` (unlimited).
